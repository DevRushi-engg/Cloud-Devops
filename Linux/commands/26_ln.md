# ln — Create Links (Symbolic and Hard)

## What it does
Creates a link — a second way to reach the same file.
Two types: symbolic links (shortcuts) and hard links (second real names).

## Syntax
```bash
ln -s /var/log/app.log latest         # symbolic link
ln original.txt twin.txt              # hard link
ls -l latest                          # shows the arrow →
```

## My Terminal Output
```bash
rushi@rushi:~/project$ ln -s ~/project/config/app.conf ~/project/latest.conf
rushi@rushi:~/project$ ls -l latest.conf
lrwxrwxrwx 1 rushi rushi 35 Aug 11 latest.conf -> /home/rushi/project/config/app.conf
```

## Symbolic vs Hard Links
| | Symbolic Link | Hard Link |
|--|--------------|-----------|
| Created with | `ln -s` | `ln` |
| If original deleted | Link breaks | Data still exists |
| Can cross filesystems | Yes | No |
| Can link folders | Yes | No |
| Shows in `ls -l` | Arrow `->` | Looks like normal file |

## Key Points
- Symbolic links are what you will use almost always
- Hard links share the actual file data — deleting one name keeps the other
- A broken symlink points to nothing — shown in red in most terminals
- Perfect for "current version" shortcuts: `latest -> v2.1/`

## When I use this
Creating shortcuts to config files, pointing a `current` symlink at the latest release folder.
