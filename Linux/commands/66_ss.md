# ss — Show Open Ports and Network Connections

## What it does
Lists open network ports and active connections.
Confirms whether a service is actually listening on the expected port.
Modern replacement for `netstat`.

## Syntax
```bash
ss -tulpn                   # all listening ports with PIDs
ss -tulpn | grep :80        # is port 80 open?
ss -tulpn | grep :22        # is SSH listening?
ss -t                       # active TCP connections only
```

## My Terminal Output
```bash
rushi@rushi:~$ ss -tulpn
Netid  State   Local Address:Port  Process
tcp    LISTEN  0.0.0.0:80         users:(("nginx",pid=1234))
tcp    LISTEN  0.0.0.0:22         users:(("sshd",pid=890))
tcp    LISTEN  127.0.0.1:5432     users:(("postgres",pid=567))

rushi@rushi:~$ ss -tulpn | grep :80
tcp    LISTEN  0.0.0.0:80         users:(("nginx",pid=1234))
```

## Flags
| Flag | What it does |
|------|-------------|
| `-t` | TCP connections |
| `-u` | UDP connections |
| `-l` | Listening ports only |
| `-p` | Show the process name and PID |
| `-n` | Show numbers not names |

## Key Points
- Always use `-tulpn` together — it is the standard combination
- `0.0.0.0:80` means listening on all interfaces — publicly reachable
- `127.0.0.1:5432` means listening on localhost only — internal only
- Use this after installing a service to confirm it actually started listening
- `netstat -tulpn` is the older equivalent — still works but deprecated

## When I use this
After starting nginx or any service — confirming it opened the
right port. Debugging "connection refused" errors.
